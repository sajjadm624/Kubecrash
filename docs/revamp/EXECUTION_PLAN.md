# KubeCrash Revamp Execution Plan

## Mission
Build KubeCrash into the most practical Kubernetes mastery platform: incident-first, portfolio-backed, and role-path driven.

## Product Pillars
1. Real incident pressure: diagnosis under time and ambiguity.
2. Proof of mastery: scoring from behavior, not completion only.
3. Portfolio artifacts: retrospectives, runbooks, and capstone evidence.
4. Guided progression: unlocks based on demonstrated capability.

## 4-Phase Build Strategy

### Phase 1: Foundation Expansion (Weeks 1-4)
- Expand starter incidents from 5 to 10.
- Add 12 new foundation labs.
- Standardize lab schema and validation rules.
- Add regression checks for progress, scoring, and unlock logic.

Exit criteria:
- 10 starter incidents shipped.
- 27+ total foundation experiences available.
- All new labs include intro, checkpoints, quiz, and retro prompts.

### Phase 2: Advanced Academy (Weeks 5-8)
- Expand advanced track content from 16 to 24 lessons.
- Add multi-signal incidents (metrics + logs + events + traces).
- Add dynamic "what to practice next" and runbook snippet generation.
- Introduce score breakdown view per lesson.

Exit criteria:
- 24 advanced lessons shipped.
- 100% advanced lessons produce saved retrospective artifacts.
- Score breakdown visible for every advanced completion.

### Phase 3: Role Paths + Skill Graph (Weeks 9-10)
- Ship 4 role paths: SRE, Platform, Security, DevOps.
- Implement skill graph nodes and weighted mastery score.
- Enforce progression gates for role paths and capstones.

Exit criteria:
- Role path UI and gates active.
- Learner profile shows skill graph and mastery score.
- Unlock decisions are deterministic and test-covered.

### Phase 4: Capstones + Launch Readiness (Weeks 11-12)
- Build 5 portfolio-grade capstones.
- Add rubric-based grading and exportable outcomes.
- Finalize performance and content QA for launch.

Exit criteria:
- 5 capstones complete with rubrics.
- Portfolio export package available.
- Launch checklist signed off.

## Non-Negotiable Quality Rules
- Every lesson has: context, objective, checkpoints, quiz, retrospective.
- No score farming: first-time completion points only.
- Every unlock rule must be explicit, predictable, and explainable.
- Every incident should teach a reusable mental model.

## Weekly Operating Rhythm
- Monday: scope lock and acceptance criteria freeze.
- Tuesday-Thursday: build and content integration.
- Friday: QA pass, telemetry review, and release.
- Saturday: learner feedback triage and roadmap adjustments.
